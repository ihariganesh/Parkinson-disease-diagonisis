## 🎓 Viva Points

### Why This Approach?
**Q: Why invitation codes instead of direct linking?**  
A: This is the industry-standard approach used by real telemedicine apps like:
- Doctor on Demand
- Teladoc
- Amwell
- MDLive

**Benefits:**
1. **Professional:** Doctors control who becomes their patient
2. **Privacy:** Patient can link/unlink anytime
3. **Scalable:** One code = multiple patients
4. **Secure:** Unique codes with expiration
5. **Simple:** Easy to explain and use

### Technical Implementation
**Q: How does the system work?**  
A: Three-phase approach:

**Phase 1: Generate**
- Doctor generates unique code (XXXX-XXXX format)
- Code stored in database with settings (max uses, expiration)
- Doctor shares code with patient

**Phase 2: Request**
- Patient enters code in their dashboard
- System validates code (active, not expired, has uses)
- Creates link request with status = PENDING
- Increments usage counter

**Phase 3: Approve**
- Doctor reviews pending requests
- Can see patient details and message
- Approves → Creates DoctorPatientAssignment
- Rejects → Patient can try another code

### Security Features
**Q: How is security maintained?**  
A:
1. **JWT Authentication:** All endpoints require valid token (except public validate)
2. **Role-Based Access:** Doctor endpoints check user.role == DOCTOR
3. **Assignment Verification:** Doctors can only see their assigned patients
4. **Code Uniqueness:** Collision prevention via database checks
5. **Expiration:** Codes can expire after configurable days
6. **Usage Limits:** Prevents code abuse (max uses)

### Privacy Controls
**Q: How does the patient control privacy?**  
A:
1. **Patient initiates:** Patient must enter code (doctor can't force)
2. **Patient approves:** Doctor must approve (patient sees status)
3. **Patient unlinks:** Can remove doctor access anytime
4. **Transparent:** Patient sees all linked doctors
5. **Reversible:** Unlink is immediate and permanent
